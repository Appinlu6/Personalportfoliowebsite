# 成长与能力图谱（Growth & Skills Map）：可交互的三维能力模型

> 状态：需求已确认大部分，节点映射待校对，尚未开发
> 记录日期：2026-10-17
> 放置位置（已定）：Resume 页的 Skills & Expertise 区块，替代现有的「年份 + 阶段标题 + 标签」列表
> 配色（已定）：白底，跟随全站；以后做深色模式时再做黑底版本

---

## 1. 为什么做

现在的 Skills & Expertise 是四个阶段的文字列表：年份、阶段标题、一排标签。它能说明「我会什么」，但讲不出两件更重要的事：

- **经历之间是怎么连起来的。** 马拉松的智能手环和现在的运动识别、智慧零售的数字营销和 Chillttoo、飞书的效能专项和现在的 Agent 工作流，这些跨越多年的连接，在列表里是断开的。
- **我是怎么一路收敛到现在的。** 早期宽、散、多分支，越往后越聚焦。这个形状本身就是故事。

目标：用一座可以拖拽旋转的「山」，让访客自己看出来，这些节点是怎么一步步组成现在的我。

## 2. 故事结构

### 2.1 一句话主线

沿用全站主线：**把复杂信息变成下一步该做的事**（From complex information to the next right action）。

山的意思：底部是多年积累的宽广基础，主线从各处汇聚、向上生长，越往上越聚焦、越亮。山顶还没到，还在长。

### 2.2 三条主线（已确认）

原始构思是：以人为本的产品与设计 / AI 与数据效能 / 数字营销与商业。已确认精简为下面三条，每条名字都是一个「方向」，而不是一个领域：

| 主线 | 中文 | 一句话 | 现在落在哪里 |
|---|---|---|---|
| **Human-Centered** | 以人为本 | 从医疗服务设计开始，始终站在人这一边 | 硕士阶段的紫荆心智、博士阶段以人为中心的 AI 研究 |
| **Data → Intelligence** | 从数据到智能 | 从让数据被看见，到让 AI 读懂数据 | 熠安：可穿戴传感器 + LLM 的人体活动识别、模型微调与评估、Agent 框架；博士阶段的 AI 研究 |
| **Growth & Business** | 增长与商业 | 从营销平台的设计者，到自己做品牌的经营者 | Chillttoo 联合创始人 |

### 2.3 山的地基：跨领域的创造力

六年设计师经历不单独成为一条主线，而是**山的地基**：它让我发现自己的天赋在跨领域的创意与创造。在模型里，地基由「视觉设计」这个二级节点体现，它连着腾讯实习、飞书官网和 Chillttoo，横跨三条主线。

### 2.4 山顶（未完成）

最上面的一级节点是 **PolyU 人工智能博士（2026 至今）**。它上方再留一个发光的、未封顶的生长点，不承载内容，只表达「还在往上长」。

## 3. 节点结构

模型里有三层：

- **中轴（经历）**：8 段工作 / 学习经历，沿山的中心竖直排成一条时间轴，从下到上。每段经历是轴上的一截线段，起点有刻度和标签。
- **一级节点（项目）**：14 个项目，分布在三条主线的山脊上。每个项目都属于一段经历，用一条细线连回中轴上对应的那一截。
- **二级节点（能力）**：24 个能力标签，也就是现在 Resume 页 Skills & Expertise 里的标签。每个能力连到它所来自的项目。

**被多个项目共享的能力，就是山上的「支线」**：比如「数字营销」同时连着腾讯营销云和用户社群，hover 时两个项目通过它一起亮起来。跨年连接不用手工画，由数据自然长出来。

### 3.5 二级节点在山上的位置

- 高度 = 它连到的一级节点的平均时间。被早期和近期经历共享的能力（如「实时物联网数据」）会落在两者之间，像一座桥。
- 水平方向在它所属一级节点的外侧，半径略大，形成山体外围的一圈「枝叶」。
- 默认比一级节点小、暗；hover 主线时，凡是连到这条主线上任一经历的能力一起亮起。

## 4. 视觉规格

### 4.1 整体形态

- **山岳轮廓**：节点和连线共同构成一座山，而不是一个实体模型。底部宽、分支多、节点散；越往上半径越小，节点越聚拢。
- **纵轴 = 时间**：从下到上对应 2017 → 现在。
- **亮度随高度增加**：底部节点偏暗、偏透明；越往上越亮，靠近山顶的节点带辉光（bloom）。
- **山顶未封顶**：顶端是一个持续向上微动的生长点，有缓慢的粒子上升，表达「还在长」。
- **三条主线各占一个方向**：俯视时三条主线大致相隔 120°，在上部逐渐向中轴汇聚。

### 4.2 配色

- 白底，跟随全站。黑底版本等站点做深色模式时再做。
- 三条主线各一个主色，地基用中性灰。颜色要克制，和站点现有的低饱和风格一致。
- 待定：具体色值在设计阶段和站点配色一起定。

### 4.3 节点

- 一级节点大于二级节点。一级节点之间的大小差异按第 8 节的优先级定。
- 一级节点默认显示短标题；二级节点默认只显示小圆点，hover 相关主线或节点时才显示文字，避免满屏文字。

## 5. 交互规格

| 动作 | 效果 |
|---|---|
| 鼠标拖拽 | 绕中轴旋转山体（限制俯仰角，避免翻到山底下）；滚轮缩放（有上下限） |
| 无操作时 | 缓慢自转；用户一拖拽就停止，松手几秒后恢复 |
| hover 一条主线（或该主线上任一节点） | 这条主线的所有节点、支线、跨年连接高亮，其余淡出到很低的透明度。效果参考 Obsidian 的 Graph View，但在三维里 |
| hover 一个节点 | 显示节点名称 + 时间的小标签；与它直接相连的节点和连线高亮 |
| 点击节点 | 相机平滑推近该节点；旁边展开概要卡片（标题、时间、角色、2–3 句概要、标签；如果有案例页，给一个「查看案例」链接） |
| 点击主线 | 山体「展开」：这条主线的节点从山上飞出，排成一条从左到右的时间轴，分支在主轴上下展开；其他节点淡出。再点一次或点「返回」，节点飞回山上 |
| 点击空白处 / Esc | 收起卡片，回到全景 |

### 5.1 降级与可访问性

- **手机**：保留旋转和点击；hover 改为点按。屏幕太小时，默认直接显示三条主线的展开时间轴视图，而不是山。
- **不支持 WebGL / 开启「减少动态效果」**：显示静态图 + 现有的文字版 Skills 列表。
- **文字版保留**：三维模型之下（或可切换）保留现有文字列表，保证搜索引擎和读屏软件能读到内容。
- **中英双语**：节点文字、卡片内容走现有的 `isCN` 机制。

### 5.2 性能

- 三维模块按需懒加载（滚动到 Skills 区块附近再加载），不影响首页和简历页首屏。
- 节点数量控制在 30 个以内，不需要实例化等重度优化。
- 目标：中端笔记本 60fps，手机 30fps 以上。

## 6. 技术方案

### 6.1 现状约束

- 项目是 Vite + React 18.3 + framer-motion + Tailwind 4。
- React 18 只能用 **React Three Fiber v8**（v9 需要 React 19）。drei 用 v9，postprocessing 用 v2。不要混用版本线。

### 6.2 方案对比

| | 方案 A：react-force-graph-3d | 方案 B：React Three Fiber 自建（推荐） |
|---|---|---|
| 是什么 | vasturiano 的三维力导向图库，Obsidian 的 3D Graph 插件就是基于它 | 用 R3F + drei 自己布局和渲染节点、连线 |
| Obsidian 式 hover 高亮 | 自带示例，几乎开箱即用 | 需要自己写，但逻辑很简单（维护一个高亮集合） |
| 山岳形状 | 力导向布局是随机的，需要用 `fx/fy/fz` 把每个节点钉在山上，等于放弃了它最大的优势 | 位置完全由数据决定：高度 = 时间，半径随高度收窄，角度 = 主线方向 |
| 点击主线展开成时间轴 | 难，需要逐帧改钉住的坐标 | 自然：节点位置在「山」和「时间轴」两套坐标之间插值 |
| 视觉精细度（辉光、山顶粒子、亮度渐变） | 受限 | 完全可控 |
| 工作量 | 1–2 天出原型 | 4–6 天做到上线质量 |

**建议**：直接用方案 B。方案 A 的长处是「自动布局大量节点」，而这个模型只有不到 30 个节点，并且布局需要精确表达时间和收敛。如果想先快速验证感觉，可以用方案 A 花半天做一个丑原型。

### 6.3 方案 B 的实现要点

- **依赖**：`three`、`@react-three/fiber@8`、`@react-three/drei@9`、`@react-three/postprocessing@2`。
- **数据**：新建 `src/app/data/growthMountain.ts`，包含五张表：主线、经历（`roles`，中轴）、项目（`projects`，一级节点）、能力（二级节点）、支线说明。经历字段：`id`、`label/labelCN`、`title/titleCN`、`start/end`、`period`、`summary`。项目字段：`id`、`roleId`、`anchor`、`line`、`title/titleCN`、`summary/summaryCN`、`skillIds`、`parentId?`（P3、P4 归属 P5）、`caseStudySlug?`。二级节点字段：`id`、`label/labelCN`。共享能力形成的连线由 `skillIds` 自动推导，不手工维护。Resume 页的文字版 Skills 列表也从同一份数据生成，保证两边一致。
- **布局函数**：`mountainPosition(node)` → `y` 由时间映射；`r = R_base × (1 − y/H)^k` 实现下宽上窄；`θ` 由主线方向加少量随机偏移（固定随机种子，保证每次一样）。`timelinePosition(node)` → 展开视图时 `x` 由时间映射，分支在 `y` 上错开。
- **渲染**：节点用球体 + 自发光材质；连线用 drei 的 `QuadraticBezierLine` 或 `CatmullRomLine`；标签用 drei 的 `Html` 或 `Text`；辉光用 postprocessing 的 `Bloom`。
- **交互**：R3F 自带指针事件（`onPointerOver`、`onClick`）；相机用 drei 的 `CameraControls` 实现拖拽和平滑推近。
- **动画**：节点在两套坐标之间用 `useFrame` 插值，或用 `@react-spring/three`。
- **概要卡片**：画布外的普通 HTML，用 framer-motion 做出现动画，和站点其他卡片风格一致。
